# GitHub authentication

gitRUST uses the GitHub App Device Flow for desktop authentication. The Client ID is public configuration. The user signs in at `https://github.com/login/device` in the system browser and enters the displayed code. The application keeps the private device code in the provider worker, waits for the server's interval, increases the delay for `slow_down`, and stops on expiry, refusal or cancellation. A separate authenticated profile request binds the resulting token to the numeric account ID.

GitHub issues short-lived access tokens when the registered app enables expiration. A later explicit operation refreshes an expired or near-expiry session. GitHub's refresh protocol for Device Flow needs the public Client ID and the refresh token. gitRUST stores the rotated access/refresh pair together in the OS credential vault. If the refresh token is invalid, expired, or the API returns a revocation response, reconnect the same account.

On Linux, gitRUST uses the desktop Secret Service with an encrypted D-Bus session. Items are scoped to gitRUST, GitHub.com, the Client ID and the numeric account ID. An unavailable vault leaves a temporary in-memory session. The workspace profile holds the public Client ID and numeric account associations only. **Load saved accounts** is explicit so opening a workspace does not prompt to unlock the keyring. Disconnect deletes local vault records and association mappings. To revoke on GitHub, use **Manage authorization on GitHub** and revoke the App in the browser.

GitHub API requests use a Bearer header on `api.github.com`. Git HTTPS operations use a repository-bound credential on the exact reviewed GitHub HTTPS URL. The Git subprocess reads the derived header from its scoped environment. Tokens are excluded from remote URLs, subprocess arguments and diagnostic output. Redirects, inherited proxy settings and custom TLS CAs are disabled for the GitHub session transport. The credential is never attempted with a different GitHub account after failure. Commit authorship continues to use the independent Git composer.
