# GitHub authentication

The primary **Sign in with GitHub** action uses Authorization Code with S256 PKCE for a gitRUST OAuth App. It opens GitHub's account picker in the default browser. After approval, the browser activates `gitrust://oauth/callback`. The original application instance validates the state, exchanges the code for a token and verifies the numeric account using `GET /user`. A pending request expires after five minutes. The account screen offers the separately selected GitHub App Device Flow for existing credentials and installations.

GitHub requires a Client Secret to exchange an authorization code or refresh a browser token. The developer provisions it in the Linux keyring. The public Client ID can be provided at build time. The provider requests expiring tokens and also handles responses without an expiration. Explicit account operations refresh expiring sessions and save the rotated pair together. A revoked or expired session requires reconnection. [OAuth App setup](GITHUB_OAUTH_SETUP.md) · [ADR-0013](adr/0013-native-browser-oauth.md)

On Linux, gitRUST uses the desktop Secret Service with an encrypted D-Bus session. Items are scoped to gitRUST, GitHub.com, the authentication method, the Client ID and the numeric account ID. Legacy vault items retain their original namespace and remain eligible only for Device Flow. Browser sign-in requires a working vault. Device Flow can retain a temporary in-memory session when the vault is unavailable. The workspace profile holds the public Client ID and numeric account associations only. **Load saved accounts** is explicit so opening a workspace does not prompt to unlock the keyring. Disconnect deletes the selected session and its association mappings. To revoke on GitHub, use **Manage authorization on GitHub** and revoke the App in the browser.

GitHub API requests use a Bearer header on `api.github.com`. Git HTTPS operations use a repository-bound credential on the exact reviewed GitHub HTTPS URL. The Git subprocess reads the derived header from its scoped environment. Tokens are excluded from remote URLs, subprocess arguments and diagnostic output. Redirects, inherited proxy settings and custom TLS CAs are disabled for the GitHub session transport. The credential is never attempted with a different GitHub account after failure. Commit authorship continues to use the independent Git composer.
