# Stage 01.1 native UI audit

Paths under `target/` identify local audit artifacts available in the maintainer workspace. Git excludes these artifacts.

The audit started from the Stage 01 working tree on `feat/design-system`, based on `a6340e6`. The actual Stage 01 release binary was saved before editing. It had 28,615,984 bytes. The changes retain graphite and copper, Source Sans 3 and Source Code Pro, native window decorations, and the egui/eframe/wgpu stack.

The reference screenshots informed the hierarchy of repository context, the density of the diff and commit inspector, and the separation of inspection panes. The audit consulted GitHub Desktop for workflow orientation, Sublime Merge and Fork for code and file inspection, SourceGit for commit metadata and list density, GitButler for visible branch context, and Rerun for native egui panel composition. ### Performance outcome

All 30 primary idle measurements met the 1% target. Stage 01.2 also found a reproducible performance defect when the filter retains focus on Wayland. The uninstrumented release used 30.6333% CPU over 60 seconds. A focused 30-second probe recorded 3,591 empty IME preedits and immediate frame requests. A scratch control reduced the work to the caret's normal timer. The stage closed visual, functional and settled idle validation without a focused text field. [Measurement details](../PERFORMANCE.md#7-stage-012-idle-revalidation)

## Stage 01.3 Wayland text editor stability

**DS-12 High.** An unchanged cursor rectangle can trigger another IME preedit through the Wayland text-input protocol and schedule another native frame. Separately, eframe's logic-only redraw fallback could disable the focused editor's IME output and cancel a pending composition. The mitigation targets native Wayland and keeps all preedit events available to text widgets, including cancellation. The diagnostic views select the initial draft control for repeatable measurements. [Performance](../PERFORMANCE.md#8-stage-013-wayland-ime-feedback) · [Accessibility](../ACCESSIBILITY.md#stage-013-wayland-text-input)

Resolved in the tested Linux configuration. All 20 focused release samples met the 1% CPU target, with a maximum of 0.6667%. Real Wayland Intelligent Pinyin input confirmed candidate selection and cancellation in the filter, draft fields and gallery inputs. The draft description retained composition during a resize and accepted new preedit after native keyboard focus returned. Stage 01.3 report (`target/stage01.3-evidence/RELATORIO.md`)

## Stage 01.4 physical Wayland validation

The final release was tested on physical GNOME Wayland with Intel graphics and wgpu/Vulkan. Three independent 60-second samples with native keyboard and text-input focus on the filter measured 0.6667%, 0.7000% and 0.6333% process CPU. The settled protocol traces recorded no cursor-area resends or IME feedback. A separate attempt with pointer input was excluded. The archived release did not sustain native focus long enough for a valid comparison in this session. The 30.6333% physical reproduction from Stage 01.2 remains historical evidence.

The physical ABNT2 check typed `aéõ` and verified that Backspace left `aé` in the filter and the gallery summary. All local gates passed with 40 tests and one previously ignored benchmark. The dependency lockfile, MSRV and security policy were preserved. Interactive graphical validation covers Linux. Windows and macOS are covered by the automated build and test workflow.

Local evidence is recorded under `target/stage01.4-evidence/`.
